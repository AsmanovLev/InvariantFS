## The one bug that mattered

The guest root filesystem was mounted **without `allow_other`**, so it belonged
to uid 0 and every unprivileged uid got `EACCES` on every file. Present since
WP66. It booted perfectly, reached `graphical.target`, served ssh as root, and
**passed every test in the repo** — because every harness asserts as root.

Fixed, merged, and confirmed:

## Why it took until now

Every earlier conclusion was an inference from an absent signal:

- "the boot stalls near `sys-fs-fuse-connections.mount`"
- "the `multi-user.target` transaction doesn't complete"
- "`/dev/shm` fails too, so it's a guest fault, not InvariantFS"

The last one is the instructive one. The "control" was run **inside the guest**,
where `setpriv`, `cat`, `head` and `ls` all live on the broken root — so the
probe could not execute its own instruments. It was never a control on
InvariantFS; it was a target reached through it. **The instrument was disabled by
the bug it was meant to detect.**

## Tooling

**GitNexus** integrated via `pi-mcp-adapter` + `~/.pi/agent/mcp.json`. Indexed
18,720 nodes / 37,445 edges / 669 clusters in 68s on 333 C files.

- Works: `impact`, `detect_changes`, `query`, `trace`
- **Known adapter bug:** `pi-mcp-adapter` coerces every non-string arg to a
  string. `summaryOnly`, `maxDepth`, `limit` all fail. Use the CLI for those:
  `node .gitnexus/run.cjs impact vol_flush --direction upstream --summary-only`
- **Verbosity:** responses run 50KB+. `--summary-only` via CLI.
- **Treat absence as absence:** the tool returns `risk: UNKNOWN` with
  *"Absence of edges is not evidence the symbol is unused."* So must we.

**Performance finding (unverified, needs measurement):** `invf_release` →
`vol_flush` at confidence 0.85. Per `src/core/invarifs.h:361`, `vol_flush`
rewrites the DEVT descriptor on every writable device. If that holds, **every
file closed through FUSE triggers a full metadata flush.** This is the likely
headline for a Phoronix-style article and is NOT yet measured.
