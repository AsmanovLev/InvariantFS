## Verdict up front
The docs describe a **better filesystem than the one that shipped**. Roughly half the documented machinery
(Text Zone/PPMd/Brotli/BCJ2, write-time CAS dedup, refcount journaling, checkpoints, throttling watermarks,
kernel module + initramfs kit, BLAKE3 verify-after-sweep) does not exist in code. Conversely, several things
that DO exist are undocumented (LZ4 default codec, 36-byte CRC'd journal entries, INOD record framing,
offline dedup). The de-facto spec is `invarifs.h` + the volume layer (`volume.c` + `vol_*.c`), NOT the docs.
A fresh implementation built from doc/02 would produce volumes this code cannot mount (and vice versa).

**2026-08-31 update:** since the original audit the code side moved a lot: WP1/WP2-v2 (full POSIX
metadata + 27-op FUSE table), WP4ab (streaming writes, flock), WP10/WP11 (Text Zone, codec registry,
POSIX tool exec), WP13/WP14/WP16 (codecpacks/containerpacks incl. the JXL lane as a pack), WP17
(FUSE tuning), WP18 (resize), WP19 (heat), WP20 (seal parity), WP21 (sweep rollback) all landed.
PB1/PB2/PB8, H1/H3/H4/H7/H8 are closed in code; PB6/H9/H10 are partially closed. What still lags is
the doc/ side (its refresh is a separate lane, not this file's) plus the rows marked OPEN below.

**2026-09-04 update (the checkpoint/multidev wave + WP-DZ):** WP24-lite (read-only
time-travel mount at the live CKP0 checkpoint, `vol_open_at` / `-o at_checkpoint`),
WP25 (two-device volumes: DEVT descriptor, metadata mirror, dev0 tier arena, RAW
mirror, degraded mount), WP26 (the `raw_watermark` reclaim rung of the doc/12
ladder), WP12c (PNGR/FLACR POSIX transcode bodies — PB6's last half, the PB6 row
is now FIXED), WP12d completion (Landlock sandbox on pack/tool children), WP-A
(POSIX ACLs + daemon-side enforcement) and cfix (compaction refuses under a live
CKP0 — the rollback-horizon rule) all landed. WP-DZ then replaced the fixed
mkfs-time RAW/Shadow split with advisory zone extents over the shared free pool:
the RAW→SHADOW "spill" (which tagged overflow segments BINARY and hid them from
the sweep forever) is gone — raw-class blocks keep `zone=0` wherever they land.
Per-WP rows in §5; user-facing docs in doc/02, doc/06, doc/12, README-LINUX.md.

**2026-09-26 update (WP83/WP86, the Meta-v3 recovery lane):** the v2→v3 cut
over left the A4 recovery chain half-built on the new default format. WP86 closed
the metadata half (a torn base page is contained and repairable, a torn root is
EIO instead of "absent", a damaged save point is refused) — the "v3 repair is a
follow-up WP" note in `fsck.c`/`vol_fsck.c` is now resolved and the v3 branch of
`fsck -f` really repairs. The content half is still open: the content cut
(`INVFS_FSCK_CONTENT=1`) and `--repair` (seal2) are v2-only passes, which is what
the remaining flakey leg-5 gate trips over. See the WP86 row and `INCIDENTS.md`.
