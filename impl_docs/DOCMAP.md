# DOCMAP — subsystem → code map

**The code is the spec.** `src/core/invarifs.h` IS the on-disk format
definition; `docs/architecture/META.md` is the concept layer over it. The
v2-era design prose (18 files under `src/doc/`) was **deleted** — git history
keeps it, but it described a format the engine retired (L2P mapper, CKP0 /
`reten`), and 15 of 18 files never mentioned metadata store at all. Do not
reconstruct them; fix the code or write a new, `file:line`-cited doc.

This map answers "where does X live". Source layout is in `FILEMAP.md`.
The symbol/type index is generated by `tools/gen_impl_docs.sh` (`make docs`)
and **not committed**: it is a view of the current tree, so a stale copy answers
"where is X" with whatever was true when it was generated.

not a network FS driver.

## Document index

Every live document, by path. `tools/check-repo-hygiene.sh` fails when a tracked
document under `docs/` or `impl_docs/` is missing from this table: an unlisted
document is one nobody will find, which is how four `HANDOFF-*` notes, a
directory of task specs and a folder of raw measurement JSON ended up with zero
inbound references before they were archived.

Statuses are not listed here because they are structural, not prose: live docs
are in `docs/` and `impl_docs/`, finished ones are in `docs/archive/` (see its
`README.md`), and generated ones (the ctags symbol index and the doxygen browser)
are gitignored and produced by `make docs`.
