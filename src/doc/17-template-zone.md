# Template Zone — Семантическая декомпозиция

> **Статус: far-roadmap, не реализовано.** Переквалифицировано
> (AUDIT §7, 2026-08-28): это **не chunk-store**, а слой разделяемых
> ссылок / словарей — AST-рецепт ссылается на шаблон по id + residual,
> инвариант `(шаблон ⊕ residual) == оригинал` (BLAKE3). Цель —
> избыточность, до которой батчинг (WP10/WP14) структурно не достаёт:
> через ВЕСЬ том и через ВРЕМЯ (новый файл против смётанных месяцы назад;
> батч видит только окно в 4 МБ), плюс явный пиннинг («этот каталог —
> базовый слой»). Домены по осуществимости: (a) ZSTD patch_from_dict для
> версионных деревьев (Docker-слои, .rodata между версиями компилятора —
> штатный dict API, без своей дельта-математики); (b) разделение секций
> ELF/PE; (c) аудио-транзиенты CDC — ПОСЛЕДНИМ, нужен FLAC-пайплайн;
> residuals/delta — v2+.
>
> **Прежнее предусловие «refcounts (WP6)» СНЯТО**: паттерн
> владелец-инод + L2P-дубли + mark-and-sweep GC, доказанный Text Zone
> (WP10), покрывает владение без refcount'ов (а сам PB7 закрыт с WP16f).
> On-disk эскиз: `zone=3` (зарезервировано), владелец `\x01tmpl`, шаблоны
> пинятся в ARC (~10% бюджета), ARC ключуется по template_seq (GC
> инвалидирует). Прежде любого кода нужен **измеренный** довод, что явные
> шаблоны бьют WP14-батчинг на шаблонном корпусе (напр. 50 треков с одной
> ударной установкой).

Ниже — исходный текст концепции (исторический контекст; «refcount» в
эскизах читать как «владелец-инод + GC» по паттерну WP10).

Новый архитектурный уровень: InvariantFS разбирает аудио и бинарники на **структурные элементы**, а не хранит их как сплошной поток байтов.

## Концепция

```
Традиционная ФС:  file.flac = [ 100% байтов ]
InvariantFS:         file.flac = [ эталон_бочки ] + [ эталон_пиано ] + [ residuals ]
                                          ↓
                             Template Zone (эталоны, 1 копия)
```

## Audio LZ77 (Словарь сэмплов)

Sweep-воркер нарезает PCM на **транзиенты** через Content-Defined Chunking (CDC):

```
1. CDC-нарезка PCM по границам транзиентов (атаки/затухания)
2. Для каждого транзиента: BLAKE3-хэш
3. Хэш уже есть в Template Zone?
   └─ НЕТ → сохранить сэмпл как новый эталон (refcount=1)
   └─ ДА  → AST ссылается на эталон (refcount++)
4. Итог: барабанная бочка в 100 треках = 1 копия в Template Zone
```

## Дельта-кодирование (Residuals)

Если сэмпл используется **с изменениями** (громкость, эхо, транспозиция):

```
AST рецепт: { template: block_42 (эталон_бочки), residual: block_77 }

Чтение:  Оригинал = Эталон + Дельта
         (применить residual поверх эталона)

Bit-perfect инвариант СОХРАНЁН:
  - invariant check: (эталон + дельта) → BLAKE3 == оригинал
  - при несовпадении → повторная полная запись сэмпла
```

Residual-блоки — крошечные (изменение громкости = скаляр; эхо = пара коэффициентов).

## Применимость

| Домен | Что дедуплицируется | Пример |
|-------|--------------------|--------|
| Музыка | Транзиенты ударных, бас-линии | 100 треков с одинаковой бочкой = 1 эталон |
| ELF/PE | Секции .rodata, .text | Обновление компилятора меняет только .text |
| .so библиотеки | Общие функции | 10 приложений, 1 копия libc |
| Docker-образы | Базовые слои | Ubuntu:20.04 и 22.04 делят общие слои |
| ОС (rootfs) | Базовые системные файлы | /usr/share, /lib — общие для всех |

## ZSTD patch_from_dict для Docker/CI-CD

Для бинарников и Docker-слоёв не нужно выдумывать кастомный delta-формат — **ZSTD имеет нативный режим `patch_from_dict`**:

```
Базовый слой Docker-образа → ZSTD словарь (хранится в Template Zone)
Следующий слой → сжимается как ПАТЧ к этому словарю

Чтение:  слой = patch_from_dict(base_dict, compressed_patch)

Достоинства:
  - Встроено в ZSTD (не нужна своя математика residuals)
  - Декомпрессия быстрее чем кастомные дельты
  - Инвариант: bit-perfect проверка стандартная
```

То же для ELF-секций: базовый .rodata → словарь, обновлённые версии → патчи.

## Кэширование Template Zone

Эталоны имеют **read-heavy** паттерн (один эталон читается из сотен AST):

- **Высший приоритет в ARC-кэше** — пинятся в RAM
- Размер пина: ~10% от Data Block Cache
- Один эталон в RAM обслуживает сотни файлов → выигрыш колоссальный

## Инвариант

```
Sweep pipeline:
  1. CDC-нарезка → транзиенты
  2. BLAKE3(транзиент) → поиск в Template Index
  3. Найден эталон → AST: {template_id, residual}
  4. Invariant: (эталон ⊕ residual) → BLAKE3 == BLAKE3(оригинал)
  5. PASS → free RAW, refcount++
     FAIL → сохранить транзиент как новый эталон
```
